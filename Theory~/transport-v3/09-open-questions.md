# Какие данные изменят решение

[код] Продуктовый сервер отсутствует. [оценка] Все числа V3 — синтетика, граница улучшения на реальном трафике неизвестна.

1. **Корпус:** минимум 100 000 последовательных событий, ≥100 установок, 3 соседние версии игры, Android low/mid/high, ≥100 коротких и ≥100 офлайн-сессий. Разделить по установкам и времени: train версия N, validation N+1, окончательный holdout N+2. Не делить случайные события одной сессии между train/test.
2. **Байты:** исходные `payload_json` непосредственно перед отправкой и фактическое тело V1 после gzip, batch boundaries, `sent_at_client`, response bytes/headers, SDK/runtime/build, время постановки/отправки/ack. Сохранять порядок ключей и числовые лексемы. Для double/decimal дополнительно тип при Track и текст после Android JSONObject: иначе уже потерянную точность при постановке в очередь невозможно восстановить транспортом.
3. **Время и сеть:** монотонные времена foreground/background/kill, доступность сети, retries/timeouts, cold/full/resumed connections, ALPN, request/response pcap после TLS либо счётчики сокета. Credential, Authorization, install token не собирать. Нужны p50/p95/p99 возраста события при отправке и размера пачки.
4. **Хеши:** определение `placed_state_hash`, все входы, версия игры, канонизация, поведение при неудачном ходе/undo/restore. Первое состояние и контрольные снапшоты. Без этого исключить игровую реконструкцию из рекомендации.
5. **Железо:** release Android arm64, Mono и IL2CPP; p50/p95/p99 encode+compress+JNI+network, alloc/peak RSS, thermal state; 30 минут одинакового replay с батарейным профилем и контрольным прогоном. Сравнивать одинаковое расписание отправки: иначе радио подменяет эффект CPU.

[оценка] Маскирование: UUID → стабильные случайные UUID с сохранением равенств; низкоэнтропийные словари → перестановка значений равной длины; случайный hex → случайный hex той же длины с сохранением повторов; время → общий сдвиг установки с сохранением всех дельт/пауз/скачков. Строки с пользовательским содержимым не публиковать; анализировать на доверенном стенде, экспортировать длины/энтропийные категории и агрегаты. HMAC-токенизация свободного текста превращает его в случайный шум и меняет задачу сжатия. При замене хешей replay-эксперимент делать отдельно на разрешённом исходном корпусе. В SDK нельзя вшивать словарь, обученный на приватных литералах.

[оценка] Чувствительность: если доля несжимаемой нагрузки q, максимальная экономия структурного шага пропорциональна 1−q; альтернативный генератор уже уменьшил выигрыш V2 с ~72–80% до ~43%. Если только доля f событий может дождаться 100, улучшение тела V3 лежит около f·(B_same−B_100); при f=0 остаётся лишь словарь и рамка. Точный результат считать суммой байтов по пачкам, не средним процентов. При miss reference p состояние выгодно, только если saving > p·fallback_bytes + reference_bytes + update amortization.

[гипотеза] Статические вероятности и компактная нейромодель окупятся при сильных устойчивых зависимостях; нужно измерить их выигрыш сверх словаря на holdout и включить стоимость модели в загрузки/обновления. Текущие опыты этого не доказали.
