# Внедрение — план, продуктовый код не менялся

[оценка] Переход разрешать только после следующих ворот; размер на синтетике не критерий выпуска.

1. **Истина V1.** Снять корпус из `09-open-questions.md`. Зафиксировать .NET→UTF8→JSONObject→SQLite→wire lexemes. Отдельно проверить DBL_MAX, subnormal, -0, decimal scale, bool/int/float equality, NUL, U+2028/2029, непарные суррогаты, UUID/hex case, ключи 64/65, 32/33 свойства, повторяющиеся JSON-ключи. Byte-exact oracle — фактические исходные байты. Никаких сравнений Python-сериализатора с самим собой как доказательства Unity.
2. **Идентичность до сжатия.** В той же SQLite-транзакции сохранять immutable origin epoch и sequence; reset меняет credential, не ключ события. Сервер хранит ключи и SHA-256 контента. V1 ingestion также сохраняет origin/sequence и legacy event_id. Если старый сервер не сохранил пары, дождаться очистки старой очереди или передавать legacy UUID до завершения миграции. Нельзя переключать незавершённые V1 retries на новую дедупликацию без моста.
3. **Теневая проверка.** В фоне encode→decode и сравнение исходных V1 bytes-minus-event_id, без второй записи события сервером. Все несовпадения → literal kind0/V1. ≥1 млн событий всех профилей без потерь/изменения данных. Replay/порядок/пропуски, process-kill в каждой точке транзакции, restore/cloned DB, clock rollback, несколько origin в очереди. В сетевой пачке один origin.
4. **Hardening.** Лимиты до выделений, fuzz с покрытием parser+decompressor и deadline, большие window, завышенные длины, alias cycles/forward ref, повтор dir/shape keys, uint64 и int64 overflow, отрицательные дельты, zero RLE, truncation, trailing frames, dictionary miss. Неподтверждённые строки не удаляются. Устойчивое серверное хранение до ack.
5. **Android.** JNI ABI/16 KiB page alignment, arm64-v8a/armeabi-v7a по поддерживаемым устройствам, IL2CPP stripping, Mono exception path; тест на реальном release APK/AAB. Принять только при p99 <5 мс encode+compress для cap100 на целевом midrange (предлагаемый бюджет, не измерение), без ухудшения frame-time и battery versus equal-cadence V1. Измерить размер split APK, не переносить AAR zip-size напрямую.
6. **Canary:** 1%→5%→25%→100%, не менее 24 ч каждой ступени и период офлайн retention до удаления V1 поддержки. Метрики: wire_B/event (оба направления), fallback, mismatch, dict miss, latency, CPU, duplicate conflict, retry, data loss. Нулевая терпимость к подтверждённой потере/изменению контента; любой conflict или mismatch останавливает расширение и сохраняет очередь.
7. **Сначала cap/deadline отдельно.** Словарь64 и рамка на прежней cadence; затем cap100/deadline60/120 только при согласованном продуктом SLO свежести. Pause/explicit Flush отправляют сразу. Для редких событий ожидание большего cap не должно превращаться в вечную задержку. При падении процесса pending остаются на диске.
8. **Откат:** capability выключает V3; отправляются исходные queue rows через V1 с тем же серверным dedup key bridge. Старые immutable dictionaries остаются доступными не меньше retention+retry horizon; истечение cache восстанавливается stateless resend, без удаления данных. Взаимосвязь новых credential со старым origin выдаёт сервер; произвольный origin от клиента не авторизован.
