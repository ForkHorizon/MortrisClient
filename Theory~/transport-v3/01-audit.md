[оценка] Нижний предел криптографического хеша зависит от модели: при неизвестном алгоритме это непрогнозируемый литерал; при известном алгоритме и всех входах это 0 условных бит после начального состояния. Ни один из этих случаев не даёт универсальный Shannon floor 11 Б/событие.

## Окончание аудита: воспроизведение и влияние ошибок

[измерено] Полный `run_all.sh` завершён в `06-experiments/v2-reproduction/`, exit 0, `results/v2-run-all.log` заканчивается `done`. **12 проверенных детерминированных артефактов совпали байт в байт**, включая обе матрицы размеров, conservative/stateful, oracle roundtrip и hex-пример (`results/reproduction-check.json`). CPU и TLS ожидаемо отличаются. Это подтверждает арифметику исходных чисел, но не их применимость к продакшену.

[измерено] Новый paired test seed101/train202: base 8944 событий/321 пачка, rich7899/288, независимый alt5400/176. V2 body c полной внешней рамкой2Б: 22,839 / 47,813 / 143,463 против V1 gzip1 113,766 / 172,365 / 251,995 Б/событие. Экономия 79,9% / 72,3% / **43,1%**. C3 подтверждено для исходной синтетики и опровергнуто как универсальный диапазон.

### Честность данных и сравнения

[код] Seed2 не содержит seed1 событий: это **не утечка тестовых записей**, но сильное совпадение распределений и схем. Два профиля base/rich не два независимых генератора. Rich построен добавлением придуманных шумных полей ради двух агрегатов, значит одинаковый gzip размер не доказывает одинаковую conditional entropy. Фиксированные4-событийные цепочки и дубли благоприятны моделям; random float mantissas вредят TSDB predictors; 5 устройств и2 версии благоприятны словарю; сериализованная доска с иной структурой могла бы поменять оба эффекта.

[измерено] Alt с независимой логикой: rare80, непохожие английские ASCII ключи, многоязычные значения до520Б, randomhex320, sparse checkpoint600, release drift посередине, случайные размеры1/3/7/25/50/100, clock gaps до90с. Все в пределах валидатора. Другой язык **ключей** из задания нельзя смешать с текущим контрактом: кириллица отвергается EventValidator. [измерено] Отдельный unicode_keys.py с китайским префиксом ключей: 1800 событий, 146,235 Б/event с собственным dict16; исходный legal alt на том же подкорпусе145,651. Это sensitivity для будущего контракта, не результат нынешнего SDK.

[измерено] Обученный base dict на rich:56,59 против своего47,81; на alt151,25 против своего143,46. Без словаря alt154,80. Вывод «словарь43–45% на JSON» не переносится на все данные: собственный alt JSON dict179,99 против gzip251,99 =28,6%, и это ещё совпадающий генератор train/test.

[код] JSON, MessagePack, CBOR, оба Protobuf в V2 получили **свои**16KiB dictionaries, gzip1/6/9, Brotli5/11, zstd3/19. Это достаточно честная матрица для проверенных настроек. Но конкурентные компактные codecs имеют out-of-band REG IDs без стоимости manifest и float32 truncation для произвольных double — такие размеры нельзя считать доказательством взаимозаменяемости. Brotli built-in dictionary активен автоматически; внешний custom Brotli не измерен. Новые ultra/LDM/PPMd результаты в `04-options-comparison.md`.

### Устройство и безопасность

[измерено] Пинованный zstd-jni AAR1.5.7-6:1 143 376Б; arm64 `.so`603 960Б raw /261 876Б ZIP; armv7 478 512/256 332. Все4 ABI raw суммарно≈2,50МБ. Это сравнимая SDK-стоимость, а не «словарь16КБ»: считать ABI splits и фактический Unity release APK. [источник] JNI Android поддерживается автором [zstd-jni](https://github.com/luben/zstd-jni), но это не тест IL2CPP. [оценка] AOT/JNI wrapper, stripping, page alignment и батарея остаются release gates.

[измерено] C12 desktop timing V2 воспроизведён в `v2-reproduction/results/cpu.md`; новые timings включают создание Python compressor и конкуренцию фоновых прогонов, их нельзя напрямую сравнивать с cached CDict в V2. Android <1мс не подтверждено. [источник] [Android](https://developer.android.com/develop/connectivity/network-ops/network-access-optimization) рекомендует группировку сетевой активности; процента экономии батареи здесь нет.

[оценка] Сервер ограничивает и compressed bytes, и decompressed bytes/window, количество объектов/строк/полей, checked arithmetic, CPU deadline; policy и auth до дорогого decode. NoBackup не защищает от ручного клона, rollback снимка или root restore. Credential обязан авторизовать immutable origin, иначе произвольный origin даёт подмену; TLS не заменяет server dedup. При conflict нельзя подтверждать/удалять строку. Метаданные и интервалы dedup нельзя удалять раньше возможного retry/replay horizon. C13 поэтому остаётся частичным, даже после исключения reset rewrite.
