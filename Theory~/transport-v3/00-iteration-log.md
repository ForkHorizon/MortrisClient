# Журнал проходов (2026-10-16)

[оценка] «Лучшая цифра» всегда привязана к корпусу, размеру пачки, гарантиям и модели. Обнаружение меньшего числа не означает готовность выпускать codec. Значения base/rich/alt в Б/event, включая соответствующую рамку.

1. **Проход0, аудит до поиска улучшений.** Прочитаны V2 summary/review/ablation/spec/options/questions, эксперименты и SDK. До поиска записаны первоначальные C1–C15 и adversarial script. [измерено] NUL,−0,double17,uint64max проходят; DBL_MAX и typedCTXREF ломают общий контракт, varint пропускает70бит. [код] ~11Б floor неверен из-за deterministic hash. Фоновый fullrunV2 запущен в копии и позднее подтвердил12 byte-identical артефактов. Текущая исходная цифра V2 на новых seeds22,839/47,813/143,463.
2. **Проход1, проверка переноса и первые альтернативы.** [измерено] Независимый alt даёт всего43% экономии V2; base-dictionary устаревает даже на rich. PPMd на независимых пачках хуже zstd-dict. 64KiB dictionary даёт21,648/44,747/138,312 без новой рамки; V3 same cadence21,756/44,856/138,418. [измерено] Numeric linear<2%, XOR/prefix хуже; hash rule отдельно17,931/42,360/143,463, нельзя переносить на настоящую игру. Рекомендация — сохранить columnar, добавить exact escape/bounds и проверить cap.
3. **Проход2, целевые пачки/обучение.** [измерено] V3 cap100 oldtraining17,800/39,812/129,568; matchedtraining64 даёт17,051/38,084/129,506. Первое сравнение predictors использовало разную baseline-тренировку: оно могло ошибочно приписать per-type выигрыш2,8%rich. Пересчитано с таким же обучением baseline; преимущество исчезло. Оба predictor и baseline имеют свои matched dictionaries, нельзя выбирать только удобный denominator. Это последняя принятая универсальная комбинация.
4. **Проход3, сильные модели, предел и надёжность.** [измерено] Field/currenttype/previoustype arithmetic проигрывает no-dictzstd даже на value stage; Markov выигрывает на deterministic game, не на alt. History4 лучше V2singleprev, но чувствителен к miss. Sparse strings проиграли. [измерено] Extreme cap500+rule1+dict64 exact frame roundtrip даёт8,334/29,088/123,045. Это ниже ошибочного11Б floor; не новый lower bound. [измерено] Внешний V3 fuzz сначала поймал MemoryError из corrupted content-size; исправлен preflight header/window/content check. Затем8233событий и2000мутаций прошли. CPU всего Python pipeline миллисекунды, нельзя обещать телефон<1мс.
5. **Проход4, первый финальный проход без улучшения>2%.** [измерено] `final_passes.py`: к лучшему extreme добавлены linear/per-type predictors, каждый со своим обученным на cap500dict64. Base9,156/8,886 хуже8,334; rich30,294/29,671 хуже29,088; alt122,974/123,401 против123,045 (лучшее0,058%). Рекомендация и лучшая цифра не изменились.
6. **Проход5, второй финальный проход без улучшения>2%.** [измерено] Тот же лучший baseline, ultra22/LDM: base8,3317/8,3321;rich29,0852/29,0868;alt123,0635/123,0454. Максимальная экономия≈0,0282%, ниже2%; CPU/сложность растут. Лучший практически выбранный extreme остаётся8,334/29,088/123,045, рекомендуемый17,051/38,084/129,506.

[оценка] Остановка по правилу двух последних проходов <2%. Это локальное прекращение проверенных направлений, **не доказательство** достижения Shannon limit или глобальной оптимальности. Более сильные probability models, FSST/полные Chimp/Elf и real-game replay остаются открытыми с точными данными в09. Без реального корпуса новые архитектуры имели бы всё больший риск подгонки под synthetic.

[измерено] Все V2 source/docs SHA256 сохранены и повторно проверены extras.py; product diff отсутствует. Документы V3 сгенерированы/проверены по JSON raw results. Дубликаты сырых результатов и виртуальное окружение остаются локальными, в продукт ничего не добавлено.
