# Transport V7: финальные выводы

17 октября 2026. Исследование завершено по решению пользователя: сохранить
полученные результаты и закончить V7 без новых экспериментов. Это завершение
исследовательской работы; исходные критерии эффективности достигнуты не полностью.
Production SDK, Puzzle и сервер не изменялись, рабочим транспортом остаётся V1.

## Главный результат

Универсальная схема «каталог проекта → колонки → числовые/строковые модели →
zstd со словарём проекта» реализована в исследовательских прототипах. Реальные
пакеты C# успешно читает независимый Go decoder. Игровые правила очистки Puzzle
вынесены в отдельный эксперимент и не встроены в общий codec.

Гипотеза, что словаря 16–32 КиБ достаточно для достижения исходных размеров,
**не подтвердилась**. Лучший проверенный основной вариант даёт следующие размеры:

| Представление | Б/событие | Условия |
|---|---:|---|
| Реконструированный V1 JSON + gzip1 | ≈122,57 | Исходные события и UUID |
| V7, исходные игровые поля | 17,425535 | dict32, identity по origin/sequence вместо event UUID |
| V7, условная игровая очистка | 9,057567 | dict32, дополнительно удалены выводимые дубли и interaction GUID |
| V7, очищенные поля с исходным event UUID | 25,934019 | dict16; отдельная конфигурация, не прямой контроль dict32 |

Два основных V7 результата подтверждены фактическим C# packet output:
1 114 241 и 579 168 Б на 63 943 события соответственно. В каждом варианте
653 M7-пакета содержат 63 743 события; остальные 200 событий неизвестной схемы
оплачены полным V1 gzip fallback. В сумму включены M7 header, dictionary ID и CRC;
HTTP/TLS, setup, ACK и повторные отправки не включены. Размеры V1 восстановлены
из DB jsonb: исходных HTTP-байтов, порядка ключей и границ production-пачек нет.

Ни 17,43, ни 9,06 Б нельзя обещать как немедленный результат обновления SDK:
оба варианта требуют миграции identity, а второй — ещё и игровой семантики.
Случайный исходный event UUID сам несёт около 16 байт информации на событие.

## Статус исходных критериев

| Критерий | Итог V7 |
|---|---|
| Сырые данные <11–13 Б/событие | Не достигнут: основной кандидат 17,43 Б даже без исходного event UUID |
| Очищенные данные <5–7 Б/событие | Не достигнут: условный кандидат 9,06 Б |
| Телефон: <3–5 мс на 100 событий | Не проверен на физическом телефоне |
| Unity C#: 0 managed GC | Подтверждён для подготовленных колонок + reused native zstd; весь SDK не проверен |
| Полный M7 packet без managed GC | Подтверждён на .NET host с подготовленным вводом; Unity framing не измерен |
| Универсальный движок без правил Puzzle | Соблюдено в прототипах; production-интеграции нет |

Unity Editor и Android ARM64 Development IL2CPP на эмуляторах с 4/16-КиБ
страницами прошли 16 fixtures каждый, по 1000 упаковок, с совпадением raw bytes
и калиброванным GC.Alloc. Средние времена этапа для реальных пачек из 100 событий
составили около 0,14–0,20 мс на эмуляторах. Это не время всего SDK, не p95/p99
и не доказательство отсутствия нагрева или потери FPS на телефоне.
Unity GetAllocatedBytesForCurrentThread оказался stub; результат GC опирается
на ProfilerRecorder с положительным контролем аллокации.

C# framing проверен на 18 protocol records по 1000 повторений с нулевыми
managed GC bytes. Независимый Go decoder прочитал 1316 пакетов / 128 787 событий
(повторные представления того же корпуса и fixtures), восстановил typed values,
IEEE float bits и Decimal lexemes; 112 malformed/auth-invalid пакетов отвергнуты.
Raw-body fuzz выполнил 616 422 итерации за 10 секунд. Это ограниченная проверка
offline codec, а не готовый HTTP receiver с persistence и ACK.

## Что установлено в Puzzle

- `wave_attempt_id` совпадает с `attempt_id` в проверенном дне; источник заполняет
  их одним значением. Дублирование подтверждено в исследованном коде и данных.
- SHA совпал с CSV в 286 265 проверенных случаях, несовпадений не найдено.
  Однако игра может не отправлять CSV длиннее 1024 UTF-8 байт, сохраняя hash.
  Удалять hash можно только при наличии полного CSV, совпадении SHA и отсутствии
  truncation. Backend должен восстановить его до существующих потребителей.
- Для 509 790 наблюдений interaction не найдено коллизий составной пары.
  Но отложенный PlayerPrefs.Save допускает повтор индекса после crash.
  До удаления GUID нужны durable counter и миграция backend/dashboard связей.
- Текущий ResetIdentity переписывает install_id очереди. Замена event UUID
  требует immutable origin и устойчивого sequence/dedup контракта для reset/retry.

Эти проверки показывают условия будущей миграции, а не разрешают безусловное
удаление полей. Подробности и зависимости: [аудит игры](01-game-deduplication-audit.md).

## Неподтвердившиеся гипотезы и полезные наработки

Числовые модели и prefix/suffix string tables улучшили результат обычного V6
со словарём. Отдельные metadata tables ухудшили cleaned размер до ≈9,73 Б и
не приняты. Межколоночный Python probe дал оценку ≈17,15/8,77 Б, выиграв около
0,28 Б/событие при ≈26 мс на 100 событий: это отдельный raw-column эксперимент
без согласованного M7 flag и native/Unity реализации, не итоговый транспорт.
Диагностическое обнуление колонок удаляет информацию и не является lossless
результатом; его выигрыши нельзя складывать или включать в итоговые размеры.

Сохранены универсальные каталоги, ограниченный M7 framing, C# encoder,
независимый Go decoder, контрольные фикстуры и воспроизводимые scripts.
Доставка/версионирование assets через handshake, выбор транспорта в SDK,
durable aliases, очередь/ACK/retry, серверное сохранение и миграции потребителей
не реализованы. Подготовка DTO, parsing и schema lookup не входят в zero-GC proof.

## Решение по завершении V7

Оставить V1 в production и сохранить V7 как исследовательский snapshot.
Кандидатом для возможной отдельной будущей работы остаётся универсальный
columnar + numeric/string models + dict32. Исходные трафиковые цели не объявлять
достигнутыми; миграции игры не смешивать с выигрышем общего codec.
Новых экспериментов, подключения устройств или внедрения в рамках V7 не требуется.
